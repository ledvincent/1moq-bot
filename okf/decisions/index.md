# Decisions

* [Claude through the Anthropic API profiles, classifies and writes](MOQ-1-claude-for-ai.md) - One AI provider, Claude Haiku 5.5 through the Anthropic API (Batch API, prompt caching, monthly spend cap), with extraction of facts from untrusted page text kept apart from writing, and every output checked by code
* [Every email is checked by the send gate at the moment it is sent](MOQ-1-send-gate.md) - Emails are planned ahead as one row per lead and step, and each is claimed and checked in one transaction right before it goes to the mailbox (approval, opt-out, reply, window, limits, footer), so a late reply or withdrawal is never missed and nothing is sent twice
* [Lead sources only through official or provider APIs, never the company's Instagram account](MOQ-1-lead-source-policy.md) - Google Maps and Instagram data come only through official APIs (or a provider's API if the client chooses), the tool never signs in to or automates the company's Instagram account, and lead websites are read politely
* [Libraries and pinned versions for the scaffold](MOQ-2-libraries-and-versions.md) - pnpm, Drizzle, pg-boss, Vitest, ESLint, Prettier and Luxon on Node 24 with exact version pins, TypeScript held at 6.0.3 until typescript-eslint supports 7; versions change only through a ticket
* [One package, one folder per module under src](MOQ-2-folder-layout.md) - One package (no monorepo) with the server in src/<module>/, the UI in web/, tests next to the code and shared platform code in src/platform; a module's folder is created by the first ticket that needs it
* [Personal data: EU hosting, minimal data, hashed do-not-contact list, retention](MOQ-1-personal-data-handling.md) - Leads' data is processed on legitimate interest, hosted in the EU, limited to business facts and contacts with their sources, deleted after retention periods, while opt-outs are kept for good as a keyed hash of the address
* [PostgreSQL is the only data store and holds the job queue](MOQ-1-postgresql-store-and-queue.md) - PostgreSQL on the same server as the service holds all data and the background job queue, with a daily backup kept off the server, so a restart never loses a planned send and the do-not-contact list is never lost
* [Send and read through the company mailbox, plain personal emails, no tracking](MOQ-1-company-mailbox-sending.md) - Outreach emails go out from the company mailbox and replies and bounces are read from it, as plain personal emails with no open or click tracking, so replies land where the owner reads them and delivery is not hurt
* [The page is served by an always-on web service in the cloud](MOQ-1-cloud-web-service.md) - One web service on a small always-on EU server serves the owner's UI and runs all background work, so emails, follow-ups and unsubscribe work while the owner's Mac is off, within €10 a month
* [TypeScript on Node.js with Fastify and React, one deployable](MOQ-1-typescript-stack.md) - TypeScript everywhere on the current Node.js LTS, a Fastify API serving a React UI built with Vite, web server and job worker in one container, so one language covers the UI, the API and the jobs
